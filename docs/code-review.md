# Code review – Study Notes

Review of the whole project at commit `c19f3c8` (main, after "Merge feature/chapter-notes"), checked against `CLAUDE.md` and `docs/spec.md`. No code was changed during the review.

## Summary

The code is in good shape for an internal app. Every API route validates its input, all SQL uses prepared statements, file paths never come from the user, Markdown is rendered without raw HTML, and no keys appear in the code or the logs. All model prompts match the specification word for word. Deleting a material removes its vectors, chunks and notes in one transaction. All migrations keep existing data. The test suite is broad: 191 tests over the API, conversion, chunking, notes generation, chapter detection and migrations.

The main risks are in reliability and operations, not in the core logic:

- **Timeouts and retries.** No model or embedding call has an explicit timeout. Embedding calls are not retried. Because there is only one job queue, a single hung request to Ollama or OpenAI stops all indexing and all notes generation.
- **Long jobs are fragile.** A notes job saves nothing until it is finished, and the retry window is about 7 seconds. A rate limit or a restart halfway through a book loses all the work done so far.
- **Privacy after a restart.** Jobs that are restored after a restart forget the provider the user chose. Material the user meant to process locally can then be sent to OpenAI.
- **Exposure.** The server listens on all network interfaces, has no authentication, and accepts multipart uploads from any website (a CSRF risk).
- **Blocking the event loop.** PDF extraction and chapter validation can block the server for seconds on large books. The source viewer re-downloads up to 5 MB every 3 seconds while a material is processing.
- **Documentation.** The README is out of date: it still says PDF is not supported and does not cover local models or note styles.

No critical findings: nothing loses data or exposes secrets in normal use.

### Checked and found in order

- **Prompts.** These are word for word as in the spec: the notes system prompt, the five Nadgradnja 5 styles, the generic merge instruction, the answer prompt, and the four Nadgradnja 6 prompts (candidates, section title, chapter, overview).
- **Provider rules.** `auto`, `local` and `openai` behave as specified. `ALLOW_EXTERNAL=false` refuses OpenAI. `local` never falls back to OpenAI. Embedding models are left out of the model list.
- **Schema.** The schema follows the spec plus documented extensions: `style`, `page_offsets`, `outline` and `chapters`. Migrations run in transactions (the materials rebuild runs with foreign keys off and checks them afterwards).
- **Deleting materials.** Vectors, chunks and the material are deleted in one transaction, and notes are removed by cascade. An index job writes nothing if the material was deleted while embeddings were being computed. A notes job for deleted notes finds no row. Notes ids use AUTOINCREMENT and are never reused.
- **XSS.** No `dangerouslySetInnerHTML`, no `rehype-raw`. react-markdown's default URL filtering is in place, and source text is rendered as React text.
- **Secrets.** The key is read only from `OPENAI_API_KEY` and never logged. Usage logs contain only token counts. `.env` is in `.gitignore`.
- **Configuration.** Paths, URLs and ports come from environment variables. `vite.config.js` builds the proxy URL from `PORT`. Tests bind to `127.0.0.1` on random ports.
- **Restarts.** Materials and notes still in `processing` are queued again on start, and stored chapter detections are reused.

## The 5 most important fixes

1. **Add timeouts and retries to all model and embedding calls (R1, R2).** One hung or failed Ollama request currently stops the whole job queue, or loses a book's indexing.
2. **Store the requested provider and model with each notes job (R4).** After a restart, material meant for the local model must not be sent to OpenAI.
3. **Bind to `127.0.0.1` by default and reject cross-origin state-changing requests (R5).** Without login, the network interface and the multipart CSRF are the only access control.
4. **Keep long jobs from losing work, and keep the server responsive (R3, R6, R8, R9).** Store partial summaries and respect `Retry-After`. Move PDF extraction to a worker. Make `validateChapters` linear. Stop polling the full material content.
5. **Make chapter detection fail loudly on infrastructure errors (R7).** Only "unusable reply" errors should move on to the next method. A network or auth error must not be stored as a permanent, weaker chapter detection.
